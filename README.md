# ProxyLair public showcase

A self-contained, static public portfolio for ProxyLair (ADR-014). Plain
HTML/CSS/JS — no framework, no build step, no server runtime. Deliberately
separate from HIRO/Jarvis: no dependency on `src/api`, Sheets, or the
Command Router. Not a shop — no selling, no checkout, no order form.

## What's in Phase 1

Hero, Gallery (card-flip + per-card "watch the build" link), Process,
Watch/content-hub, Contact — the 5 sections confirmed in ADR-014. Gallery
content is currently **placeholder only** (4 fictional sample cards,
generated by `tools/generate_placeholder_cards.py`, clearly labeled as
samples) — no real card art until you curate one via HIRO's future
"Publish to Showcase" step (ADR-014 2.3, not built yet).

### Visual direction (in progress, iterating)

The repo root (`/`) is always the **current primary candidate**. History
so far:
1. HIRO's neon-cyan-on-dark console look (rejected — too cold/internal-
   tool for a public storefront).
2. Warm ivory/parchment + brass accent + Fraunces serif, kept viewable at
   `/ivory/` (a full, independent, self-contained copy — its own CSS/JS/
   assets, doesn't share files with the root).
3. **Current primary**: black & white foundation + a purple accent (a
   restrained touch of neon-glow reserved for a couple of hover moments
   only — the primary CTA and each card's own art-accent hover ring, not
   the page in general), headers set in **Cormorant** (see below for why).

Structure, sections, and all interaction logic (flip, lightbox, plate
numbering) are identical across every direction — only `styles.css` and
the font `<link>` in `index.html` change between them.

### Header typeface

The wordmark (`design_engine_v2/reference/brand/proxylair_wordmark.png`)
is a high-contrast display serif with dramatic hand-drawn-looking swash
tails on its two large capitals (P, L) and a small-caps treatment for the
rest of the letters — closer to vintage gothic-glamour/Didone poster
lettering than to true blackletter/fraktur (the strokes are smooth
curves, not broken gothic strokes, which rules out fonts like
UnifrakturCook despite the "gothic" association). It doesn't match any
single free Google Font exactly — logos like this are typically hand-
lettered or heavily customized from a base face specifically so they're
distinctive — so headers use **Cormorant** as the closest freely
available match in contrast and proportion (Cinzel and IM Fell were also
considered and ruled out: Cinzel reads as carved-stone Roman capitals
with no flourish; IM Fell has an aged/distressed texture and different
proportions). The wordmark image itself is still used as-is for the
logo/nav — this only affects headings set in live text.

## Gallery manifest (`data/cards.json`)

The gallery reads this file directly in the browser. A future HIRO
publishing step replaces it (and copies referenced images into `cards/`)
— no page code needs to change.

```json
{
  "version": 1,
  "cards": [
    {
      "id": "stable-kebab-case-id",
      "image": "cards/card-art.jpg",
      "printImage": "cards/finished-print.jpg",
      "title": "Display title",
      "game": "Game or category",
      "style": "Style · Finish",
      "caption": "Optional detail-view description",
      "socialPostUrl": "https://specific-post.example/video",
      "featured": true,
      "accent": "#00e5ff"
    }
  ]
}
```

| Field | Required | Purpose |
| --- | --- | --- |
| `id` | yes | Stable, unique, URL-safe. |
| `image` | yes | Card-art face (front of the flip). |
| `printImage` | no | Finished-print photo (back of the flip). Falls back to `image`. |
| `title`, `game`, `style` | yes | Public label text. |
| `caption` | no | Shown in the detail lightbox. |
| `socialPostUrl` | no | Powers "Watch the build" in the lightbox. Omit to hide the button. |
| `featured` | no | Included in the rotating hero backdrop. |
| `accent` | no | Per-card glow/border color. Defaults to ProxyLair cyan. |

**Publish atomically**: upload every referenced image first, validate the
full manifest, then replace `cards.json`. Never include unfinished,
customer-private, or uncurated work — this is a deliberate, per-item
decision each time (ADR-014 2.3), never a blanket sync.

`data/site.json` holds contact links, social links, and optional featured
video embeds — see the file for the shape. **The social URLs and email in
there right now are placeholders and must be confirmed before real
launch**, same caveat ADR-014 itself calls out.

## Deploying to GitHub Pages — your steps

This repo is structured to be served straight from its root by GitHub
Pages — no build, no `/docs` subfolder, no Actions workflow needed. These
are the parts only you can do (repo creation, hosting, and DNS are your
accounts, not something I can act on for you):

1. **Create the GitHub repo.** On github.com, create a new repository
   (e.g. `proxylair-showcase`), empty (no README/gitignore from GitHub's
   side — this repo already has its own).
2. **Push this repo to it:**
   ```
   git remote add origin https://github.com/<your-username>/proxylair-showcase.git
   git branch -M main
   git push -u origin main
   ```
3. **Enable Pages.** In the GitHub repo: Settings → Pages → Build and
   deployment → Source: "Deploy from a branch" → Branch: `main`, folder
   `/ (root)` → Save. GitHub will publish at
   `https://<your-username>.github.io/proxylair-showcase/` within a
   minute or two, and redeploys automatically on every push to `main`
   after that.
4. **Point `proxylair.com` at it (once you've registered the domain):**
   - Register the domain (your task, ADR-014 notes ~$12/yr).
   - In the repo: Settings → Pages → Custom domain → enter `proxylair.com`
     → Save. GitHub creates a `CNAME` file in the repo for you.
   - At your domain registrar's DNS settings, add the records GitHub's
     Pages docs specify for an apex domain (four `A` records pointing at
     GitHub's IPs, or a single `ANAME`/`ALIAS` record if your registrar
     supports one) — GitHub's own Pages settings page shows the exact
     current values to use once you enter the domain in step above.
   - Optionally also enable "Enforce HTTPS" once the certificate
     provisions (GitHub does this automatically, usually within an hour
     of DNS propagating).

Until the domain is live, the `https://<your-username>.github.io/proxylair-showcase/`
URL works immediately after step 3 and is safe to share for review — all
asset paths in this repo are relative, so the site works correctly at
that subpath, at the domain root once it's live, or from a plain local
file server.
